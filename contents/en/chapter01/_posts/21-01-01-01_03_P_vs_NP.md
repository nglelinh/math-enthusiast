**P vs NP** is a Clay Millennium Prize Problem and the central open question of theoretical computer science. In one sentence:

> If a proposed answer to a yes/no problem can be **checked** quickly, must there always be a way to **find** an answer quickly?

Most experts expect **P ≠ NP**, but the question remains open. A proof either way would reorganize algorithmics, cryptography, and much of pure mathematics that touches computation. This page is also a **language** lesson: talk of “NP problems,” “AI will solve NP,” or “my code is slow so it is NP-complete” is often imprecise. Goal: clean definitions, the NP-complete backbone, why the question resists, and what practice already does while theory waits.

**Path:** decision problems → P → NP and certificates → Cook–Levin → barriers → crypto, solvers, AI hype → confusions.

---

After this lecture you should be able to:

- Give examples of problems in P, problems in NP, and **NP-complete** problems (SAT; decision versions of coloring, TSP, etc.).
- Explain why **P ⊆ NP** is essentially immediate and why **NP ⊆ P** is the open issue.
- State the idea of the **Cook–Levin theorem**: SAT is NP-complete; polynomial-time reductions glue the hard problems together.
- Name at least one **barrier** to proving P ≠ NP (relativization; natural proofs—at slogan level).
- Connect P vs NP carefully to cryptography (cousin via hardness, not identical) and to **practical solvers** (engineering vs worst-case theory).
- Apply **LO6** to media claims: “AI solves NP” hype vs what membership in a formal complexity class actually means.

## 1. Decision problems and “quickly”

Complexity theory organizes **decision problems**: inputs with yes/no answers. Decision versions keep definitions clean; many search and optimization questions have natural cousins (“is there a solution of cost at most $$K$$?”).

Examples: Is this graph connected? Does this Boolean formula have a satisfying assignment? Is there a tour of length at most $$K$$? Does this graph admit a proper 3-coloring?

**“Quickly”** means time **polynomial** in the input size $$n$$: roughly $$O(n^c)$$ for fixed $$c$$. Exponential time ($$2^n$$, $$n!$$) is “slow” for large $$n$$. The model is idealized (Turing machines, bit inputs)—coarse on purpose, to separate broad hardness regimes rather than laptop constants.

![Polynomial vs exponential growth]({{ site.baseurl }}/img/chapter_img/pnp_poly_vs_exp_growth_quanta.jpg)

*Figure. Schematic growth rates: polynomial-time curves stay manageable longer than exponential blow-ups as input size increases (source: Quanta Magazine P vs NP video).*

**History slogans.** Turing formalized computation and showed not every problem is computable; hardware later scaled speed dramatically—yet some problems remain hard because of **algorithmic** cost. P vs NP asks about efficient algorithms in principle, not about today’s chips.

---

## 2. The class P

**P** is the class of decision problems solvable in **deterministic polynomial time**: an algorithm that, on every input, correctly outputs yes or no in time bounded by a polynomial in the input length.

Examples: many connectivity and shortest-path decisions; graph matching; linear programming in suitable models; **primality testing** (AKS). Membership in P is a positive algorithmic achievement. Proving *non*-membership is much harder—that asymmetry is part of why P vs NP resists.

---

## 3. The class NP and certificates

**NP** (nondeterministic polynomial time) is best remembered through **certificates** (also called witnesses):

> A decision problem is in NP if every **yes** instance has a short certificate that can be **checked** in polynomial time, and no **no** instance has a false certificate that passes the checker.

Examples:

- **SAT:** a formula $$\varphi$$ is a yes-instance if there is a Boolean assignment making $$\varphi$$ true; the assignment is a certificate of length linear in the number of variables.
- **Hamiltonian path:** a path visiting each vertex once is a certificate; verifying adjacency and completeness is fast.
- **Subset sum:** a subset that hits the target sum is a certificate.
- **Graph 3-colorability:** a coloring of the vertices with three colors is a certificate; checking that every edge is bichromatic is fast.

Clearly **P ⊆ NP**: if you can solve a problem quickly, you can ignore certificates and just compute the answer (the empty certificate works with a solver as checker). The Millennium question is whether **NP ⊆ P**—whether efficient verification always implies efficient solution.

**Naming trap.** **NP does not mean “not polynomial.”** It means “checkable in polynomial time with a witness” (or solvable in nondeterministic polynomial time, in the classical machine definition). Many problems believed not to lie in P are in NP; that is the interesting tension, not a definition of “hard.”

**Sudoku metaphor.** Filling a large Sudoku can require enormous search; **checking** a completed grid is quick. That is the NP intuition: hard to *find* (as far as we know), easy to *verify* when a candidate is in hand.

## 4. NP-completeness: one key to open them all

Among problems in NP, some are **hardest** in a precise sense.

A problem $$L$$ is **NP-hard** if every problem in NP **reduces** to $$L$$ by a polynomial-time reduction: an efficient transformation that maps instances of any NP problem to instances of $$L$$ so that yes-instances map to yes-instances and no to no. Intuitively, $$L$$ is at least as hard as everything in NP, up to polynomial overhead.

$$L$$ is **NP-complete** if it is in NP and NP-hard.

**Cook–Levin theorem (1971):** Boolean satisfiability (**SAT**) is NP-complete. Any nondeterministic polynomial-time computation can be encoded as a Boolean formula satisfiable exactly when the computation accepts—so an efficient algorithm for SAT would efficiently solve every problem in NP.

Karp and others then showed thousands of natural problems are NP-complete: decision TSP, graph $$k$$-coloring for $$k\ge 3$$, integer programming feasibility, scheduling and packing decisions, generalized Sudoku-as-decision, and more.

**Consequences:** if **any** NP-complete problem is in P, then **P = NP**; if **P ≠ NP**, then **no** NP-complete problem is in P. The hard-problem zoo stands or falls together under polynomial-time reductions. NP-completeness is not a vibe (“feels hard”) but a **theorem schema**: hardness transfers along reductions.

## 5. Why it is hard to resolve

P vs NP asks about the **limits of efficient computation** for an entire class of problems—not a single equation. Online “proofs” appear regularly and almost never survive scrutiny. Structural **barriers** explain why many natural strategies fail:

**Relativization (Baker–Gill–Solovay).** There are oracles relative to which P = NP and oracles relative to which P ≠ NP. Techniques that still work in the presence of arbitrary oracles (“relativize”) cannot settle the real question; much classical diagonalization relativizes.

**Natural proofs (Razborov–Rudich).** Under plausible cryptographic assumptions, a large class of combinatorial circuit-lower-bound strategies cannot separate P from NP: if a technique is too “constructive” and “large” in a technical sense, it would also break pseudorandom objects cryptographers believe exist.

**Algebrization (Aaronson–Wigderson).** A further limit on algebraic extensions of relativizing methods.

Barriers do **not** say the problem is undecidable; they say many *natural* proof styles are insufficient.

![Natural-proofs / hardness barrier metaphor]({{ site.baseurl }}/img/chapter_img/pnp_natural_proofs_barrier_quanta.jpg)

*Figure. Popular metaphor for proof barriers on the road to P ≠ NP (source: Quanta; formal statement is Razborov–Rudich natural proofs).*

**Optional depth.** One attack route is circuit lower bounds for a specific NP function (Shannon showed *most* functions need large circuits; naming a hard NP function is the obstacle). **Metacomplexity** (e.g. Minimum Circuit Size Problem) studies hardness-of-hardness and links to cryptography.

## 6. Cryptography, practice, and what rides on the answer

**If P = NP** (unexpected to most experts): many search and optimization tasks would collapse in worst-case complexity (with caveats about search vs decision). Public-key cryptography would need urgent rethinking **if** that collapse yielded efficient algorithms for the specific problems cryptosystems use. Crypto needs **average-case** hardness of particular distributions, not only worst-case NP-completeness—but P = NP would still be an algorithmic shock.

**If P ≠ NP** (majority belief): checking can be easier than solving. Brute force, heuristics, approximations, and parameterized algorithms remain the practical toolkit. How hard *individual* problems are (approximation, fine-grained complexity) stays open.

**Crypto carefully.** “Crypto is NP-complete, so we are safe” is wrong in multiple ways. Factoring, discrete log, and many lattice problems are **not** known to be NP-complete; security needs hardness on random instances. P ≠ NP would not by itself prove RSA safe forever; P = NP would not automatically print a practical factoring algorithm—but it would demolish the general wall between verification and search.

**Practical solvers vs theory.** High-performance **SAT solvers**, MIP solvers, and heuristics often crush large structured instances while worst-case NP-completeness remains. No contradiction: classes give **guarantees for all inputs**; solvers exploit structure and engineering. Theory states the ceiling; practice lives under it.

## 7. LO6: “AI solves NP” and other media confusions

Language models and heuristic optimizers can propose candidates, patterns, or code. Useful engineering—**not** a collapse of a complexity separation.

For **LO6** and seminar discussion:

- Success on many **benchmarks** does not put an NP-complete problem in P.
- A net that often finds good tours does not place TSP decision in P; “often” ≠ “always polynomial with correctness proof.”
- “AI solved NP” usually confuses **heuristic performance** with **class membership**.
- A genuine polynomial-time algorithm for one NP-complete problem would be a mathematical earthquake—and would need verification as an algorithm, not a demo on selected inputs.

Translate hype into: decision problem, resource bound, all instances vs some, certificate vs search.

---

## 8. Status (as of 2026)

Clay status: **unsolved**. No accepted proof either way. Rich surrounding theory (PH, PSPACE, circuits, proof complexity, fine-grained complexity, metacomplexity) continues to grow while the central question stays open.

## Common confusions

| Claim | Correction |
|-------|------------|
| “NP means not polynomial.” | NP means certificate-checkable in poly time (nondeterministic poly time). |
| “P vs NP is about quantum computers.” | Quantum is a different model (BQP); P vs NP is classical. |
| “My code is slow, so the problem is NP-complete.” | Need a reduction proof (or citation of one), not vibes. |
| “Crypto is NP-complete, so P ≠ NP proves RSA forever.” | Crypto needs average-case hardness of specific problems; NP-completeness is worst-case and often not known for crypto primitives. |
| “SAT solvers are fast, so SAT is in P.” | Solvers can be fast on many instances; worst-case polynomial-time algorithm is a different claim. |
| “AI solved NP / will solve NP.” | Heuristics and learning ≠ placing NP-complete problems in P; **LO6** media literacy. |
| “P = NP would end mathematics.” | Overstatement; it would transform algorithmics and much of crypto, not erase proof. |

## From surveys: barriers explain failed strategies, not unprovability

Aaronson’s long survey and the Quanta lecture stress a LO1-friendly map of **why** naive attacks stall:

- **Relativization:** there are oracles with $$\mathbf{P}=\mathbf{NP}$$ and oracles with $$\mathbf{P}\ne\mathbf{NP}$$. Any proof technique that “still works” after adding an arbitrary oracle cannot settle the real world question.
- **Natural proofs (Razborov–Rudich):** large classes of combinatorial circuit lower-bound methods are blocked if strong pseudorandom generators exist—as cryptography hopes they do.
- **Engineering coexistence:** SAT solvers, ILP, and machine-learning heuristics can be spectacular on *many* instances while worst-case membership of NP-complete problems in $$\mathbf{P}$$ stays open.

None of these barriers proves $$\mathbf{P}\ne\mathbf{NP}$$. They discipline research programs. Media claims that “AI solved NP” almost always confuse **heuristics on selected inputs** with **polynomial-time algorithms for all instances of an NP-complete problem**.

**Status (as of 2026):** still **open** (Clay). Community belief tilts toward inequality; belief is not a prize.
