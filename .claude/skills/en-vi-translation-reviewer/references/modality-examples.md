# Modality and quantifier pitfalls (EN → VI)

| English | Wrong VI tendency | Prefer |
|---------|-------------------|--------|
| must | softened to “nên” | phải / bắt buộc (if true obligation) |
| should | hardened to “phải” | nên / nên… (khuyến nghị) |
| may | “sẽ” | có thể |
| might | “sẽ” / “chắc chắn” | có thể (thấp chắc hơn may) |
| can | “sẽ” | có thể / được phép (context) |
| cannot | “không nên” | không thể / không được |
| only | dropped | chỉ |
| always / never | weakened | luôn / không bao giờ |
| at least / at most | swapped | ít nhất / nhiều nhất |
| approximately | “chính xác” | xấp xỉ / khoảng |
| unless / except | inverted condition | trừ khi / ngoại trừ |
| already / still / yet | tense drift | đã / vẫn / chưa |

# Relationship preservation

| English pattern | Guardrail |
|-----------------|-----------|
| A causes B | Do not flip to B causes A |
| A prevents B | Not “A causes B” |
| A only when B | Not “A always” |
| A unless B | Not “A if B” without negation |
| optional vs required | Keep optionality |

# Software terms (illustrative)

Keep English or use project-standard VI consistently; do not mix freely within one doc:

- deploy / triển khai  
- rollback / hoàn tác (or keep rollback)  
- rate limit / giới hạn tần suất  
- webhook (usually keep English)  
- payload (usually keep English in API docs)
